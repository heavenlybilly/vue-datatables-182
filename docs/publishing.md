# Публикация пакета в npm

Публикация выполняется из `.github/workflows/ci.yml` при отправке Git-тега
`v<version>`. Авторизация — `Trusted Publishing` через `OIDC`: npm доверяет
конкретному workflow GitHub. Секрет `NPM_TOKEN` не требуется.

## Подготовленный CI

Задание `Node 24 checks` проверяет проект, создаёт архив и манифест контрольной
суммы. Задание `Publish to npm` запускается после успеха проверок только для
тегов `v*`. Оно получает проверенный архив, сверяет версию и контрольную сумму,
затем публикует архив без пересборки через `--ignore-scripts`.

Право `id-token: write` предоставлено только заданию публикации. Используются
GitHub-hosted runners и `npm 11` с поддержкой `Trusted Publishing`.
Номер тега должен точно соответствовать версии из `package.json`.
Предварительные версии попадают в каналы `alpha`, `beta` или `rc`, стабильные —
в `latest`. Для `pull_request` публикация пропускается.

## Настройка GitHub

Для репозитория `heavenlybilly/vue-datatables-182`:

1. В `Settings → Actions → General` разрешается выполнение GitHub Actions
   и использование действий `actions/checkout`, `actions/setup-node`,
   `actions/upload-artifact`, `actions/download-artifact`.
2. В правилах защиты целевой ветки обязательной проверкой указывается
   `Node 24 checks`. Прежние требования `build` и `Node 22 checks` удаляются,
   если они остались в настройках.
3. Обновлённый файл `ci.yml` сохраняется в репозитории до создания тега.
   Тег указывает на коммит с новым workflow.

GitHub Environment в текущем workflow не используется. Создавать его для этой
конфигурации не требуется. Если позже будет добавлен `environment`, его имя
также указывается в настройках доверенного издателя npm.

## Настройка npmjs

В аккаунте npm нужны права владельца или сопровождающего пакета
`vue-datatables-182`. Наличие репозитория GitHub само по себе не предоставляет
права публикации в npm.

В настройках пакета открывается раздел `Trusted publishing` / `Trusted Publisher`.
Добавляется издатель `GitHub Actions` со следующими значениями:

| Поле                   | Значение                                  |
| ---------------------- | ----------------------------------------- |
| `Organization or user` | `heavenlybilly`                           |
| `Repository`           | `vue-datatables-182`                      |
| `Workflow filename`    | `ci.yml`                                  |
| `Environment name`     | Пустое значение                           |
| `Allowed actions`      | Разрешить прямую публикацию `npm publish` |

Имя workflow указывается без `.github/workflows/`. Только разрешение
`npm stage publish` не подходит для настроенной команды прямой публикации.
После сохранения выполняется проверка значений: ошибка имени или окружения
приведёт к отказу авторизации.

Если пакет ещё отсутствует в npm, сначала требуется создать его первоначальной
публикацией из аккаунта, имеющего право на имя пакета, затем настроить доверенного
издателя в его настройках. Для локальной публикации проверенного архива:

```sh
npm login
npm publish ./release/package.tgz --ignore-scripts --access public --tag alpha
```

Эта команда действительно публикует версию. Она используется только после
проверки архива и явного решения о выпуске. Если пакет существует, но аккаунт
не имеет доступа, сначала требуется получить права от владельца.

После успешного перехода на OIDC прежний токен публикации может быть отозван
в npm, а секрет `NPM_TOKEN` — удалён из GitHub, если он не используется другими
процессами. Удаление секрета GitHub само по себе не отзывает токен npm.

Актуальные ограничения, срок первичной активации доверенного издателя и
требования к версии npm описаны в [официальном руководстве npm](https://docs.npmjs.com/trusted-publishers/).

## Выпуск версии

До выпуска выполняются проверки браузеров и IDE из [плана релиза](major-release-plan.md).
Пример команд для новой версии `2.0.0-alpha.1`:

```sh
npm version 2.0.0-alpha.1 --no-git-tag-version
```

После обновления `CHANGELOG.md` и сохранения изменений коммитом:

```sh
git push
git tag -a v2.0.0-alpha.1 -m "Release 2.0.0-alpha.1"
git push origin v2.0.0-alpha.1
```

Номер приведён как пример; он не должен быть уже опубликован в npm.
**Отправка тега запускает публикацию.** Создание GitHub Release отдельно
не требуется. Результат проверяется во вкладке `Actions`, затем на странице
пакета в npm.

## Повтор после неудачи

Изменение настроек доверенного издателя применяется к следующей попытке.
После исправления только настроек аккаунта можно повторить неудачное задание
через `Re-run failed jobs`, если его workflow уже использует OIDC.

Повтор старого запуска использует старую конфигурацию workflow. Если исправлен
сам `ci.yml`, изменения сначала коммитятся и отправляются. Для новой попытки
используется новый тег с соответствующей версией на новом коммите; существующие
теги не перемещаются. Уже опубликованная версия не может быть опубликована повторно.

## Диагностика

- `E404`: проверяются имя пакета, существование пакета, права аккаунта и настройка издателя.
- Ошибка `OIDC`: проверяются `id-token: write`, провайдер, имя репозитория,
  workflow и окружение, а также версия npm.
- Несовпадение тега: исправляется соответствие `v<version>` и `package.json`.
- Публикация пропущена: проверяется, что запуск вызван отправкой тега `v*`, а не PR.
- Отсутствие канала `alpha`: проверяется, что версия имеет вид `2.0.0-alpha.N`.
