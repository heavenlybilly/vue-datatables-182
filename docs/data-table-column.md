# Колонка `DataTableColumn`

`DataTableColumn` описывает колонку внутри `DataTable`. Сам компонент не выводит
отдельный `DOM`-элемент. Таблица использует его параметры и слоты для построения
заголовка, ячеек, поиска и сортировки.

[Таблица](data-table.md) · [Типизация](typed-table.md) · [Оформление](customization.md)

## Параметры

| Параметр             | Тип                          | Значение по умолчанию и назначение                          |
| -------------------- | ---------------------------- | ----------------------------------------------------------- |
| `title`              | `string`                     | Пустой заголовок                                            |
| `field`              | `string`                     | `undefined`; прямое имя поля записи                         |
| `value`              | `(item: unknown) => unknown` | `undefined`; вычисляемое значение, приоритетнее `field`     |
| `searchable`         | `boolean`                    | `false`; участие в локальном поиске                         |
| `sortable`           | `boolean`                    | `false`; доступность сортировки                             |
| `sortField`          | `string`                     | Для запроса используется `field`, если `sortField` не задан |
| `width`              | `string`                     | `undefined`; размер колонки `CSS Grid`                      |
| `textAlign`          | `left`, `center`, `right`    | `left`; выравнивание содержимого                            |
| `sticky`             | `left` или `right`           | `undefined`; закрепление с выбранной стороны                |
| `textOverflow`       | `wrap` или `ellipsis`        | `wrap`; перенос содержимого ячейки                          |
| `headerTextOverflow` | `wrap` или `ellipsis`        | `ellipsis`; обрезка заголовка                               |

В типизированной паре из `createTypedTable<T>()` параметр `field` ограничен
строковыми ключами `T`, а функция `value` принимает запись `T`.

## Идентификатор колонки

`key` — стандартный ключ `Vue`, а не отдельный параметр компонента.
Явный непустой строковый `key` становится идентификатором колонки.
Если ключ не задан, он формируется как `field:<имя поля>`, например `field:name`.
Для колонки только с `value` или слотом `cell` явный ключ обязателен.

Ключи должны быть уникальны. Префикс `_internal:` зарезервирован для служебных
колонок нумерации и выбора. Индекс позиции не используется как запасной ключ.

`sort.by` содержит идентификатор колонки. Сервер получает `sortField` или `field`,
а не этот идентификатор. Для удобного управления сортировкой можно явно задать
`key="name"`; тогда `sort.by` будет равен `name`.

Колонка должна иметь хотя бы один источник содержимого: `field`, `value`
или слот `cell`. Слот `header` не заменяет источник данных.
Дубли ключей и неправильная конфигурация проверяются до обновления набора колонок.

## Значение и отображение

Поиск, сортировка и стандартное отображение используют один способ получения значения:

1. `value(item)`, если функция задана.
2. `item[field]` в остальных случаях.

`field` читает только прямое поле. Значение `field="user.name"` не раскрывает
вложенный объект; для такого случая применяется `value`.

Слот `cell` меняет только отображение. Форматированная сумма в слоте не изменяет
число, по которому выполняется сортировка. Для изменения обрабатываемого
значения предназначена функция `value`.

`null` и `undefined` выводятся как пустая строка. Остальные значения отображаются
как текст, без интерпретации `HTML` и декодирования `HTML`-сущностей.
Разметка и форматирование задаются слотом `cell`.

## Локальный поиск

В поиск включены только колонки с `searchable=true`. Сравнение выполняется
без учёта регистра: проверяется наличие поисковой строки в строковом значении.
Пробелы по краям запроса удаляются. `null` и `undefined` считаются пустой строкой.

Диакритические знаки не удаляются, `HTML`-сущности не декодируются.
Если колонок для поиска нет, запрос не ограничивает локальный набор.
`filter` не применяется в локальном режиме.

## Локальная сортировка

Допустимы строки, конечные числа, логические значения, `null` и `undefined`.
Все непустые значения сортируемой колонки должны иметь один тип.

| Тип                  | Порядок                                        |
| -------------------- | ---------------------------------------------- |
| Число                | Числовое сравнение                             |
| Логическое значение  | `false` перед `true` при возрастании           |
| Строка               | Порядок `JavaScript` без зависимости от локали |
| `null` и `undefined` | Всегда после непустых значений                 |
| Равные значения      | Сохраняется исходный порядок записей           |

Объекты, смешанные непустые типы, `NaN` и бесконечность вызывают ошибку
при активной сортировке. Проверяется весь локальный набор до пагинации,
включая записи, скрытые поиском. Неактивная колонка проверяется при выборе сортировки.
Пользовательская функция сравнения в `2.0` не предусмотрена.

## Удалённая сортировка и поиск

В удалённом режиме локальная `value` не сортирует ответ сервера.
Для сортируемой колонки требуется непустой `sortField` или `field`.
Вычисляемая колонка без `field` должна явно задавать серверное имя.

`searchable` относится к локальному поиску. Сервер получает общий `search`
и самостоятельно выбирает поля поиска.

## Слоты

### Заголовок: `header`

Слот `header` получает `{ title: string }` и заменяет содержимое заголовка.
Отдельная кнопка сортировки и `aria-sort` сохраняются. Клик по заголовку
или его слоту не сортирует; сортировка запускается кнопкой.

Для пользовательских интерактивных элементов подписи и клавиатурное управление
задаются приложением. Изменение содержимого слота реактивно и не вызывает
повторную обработку данных или запрос сервера.

### Ячейка: `cell`

| Поле `CellSlotProps<T>` | Содержание                                         |
| ----------------------- | -------------------------------------------------- |
| `item`                  | Исходная запись `T`                                |
| `key`                   | Ключ записи `RowKey`                               |
| `index`                 | Индекс видимой строки, начиная с `0`               |
| `number`                | Порядковый номер во всей выборке с учётом страницы |

При пагинации `number` вычисляется как `(page - 1) * perPage + index + 1`.
Без пагинации используется `index + 1`.

Контекст одинаков для колонок с `field`, `value` и только слотом.
Изменение порядка влияет на `index` и `number`, но не на `key`.
Для кнопок внутри ячейки применяется `@click.stop`, если действие не должно
вызывать клик строки.

## Ширина и закрепление

Порядок отображения: закреплённые слева → обычные → закреплённые справа.
Порядок внутри каждой группы сохраняется. Заголовок и ячейки используют
одинаковые размеры и порядок.

Для `sticky` требуется положительная фиксированная ширина в `px`, включая
дробные значения. Проценты, `auto`, `fr` и `calc()` не допускаются:
смещения рассчитываются суммированием ширин без измерения `DOM`.
Обычные колонки могут использовать другие размеры `CSS Grid`.

Если `width` отсутствует, используется `minmax(0, 1fr)` без `scrollX`
и `max-content` при `scrollX=true`. Автоматическая ширина определяется
всеми отображаемыми ячейками общей сетки.

При `scrollX=true` область таблицы прокручивается по горизонтали, а при
ограниченной высоте — также по вертикали. Для `stickyHeader` требуется
прокручиваемый контейнер. Сумма закреплённых ширин должна оставлять место
для остальных колонок; в узком контейнере закрепление можно снять реактивно.

## Перенос текста и `CSS`-классы

По умолчанию заголовок обрезается многоточием, а содержимое ячеек переносится,
включая длинные слова. `headerTextOverflow` и `textOverflow` изменяют эти правила.
Для `ellipsis` требуется ограниченная ширина; неограниченный `max-content`
не создаёт область обрезки.

Полный стандартный текст доступен через нативную подсказку `title`.
Для пользовательского слота подсказку задаёт приложение.
`class` поддерживает обычные привязки `Vue` и применяется к заголовку и ячейкам.
`textAlign` действует также на оболочку слота `cell`.

## Пример: сумма, закрепление и действия

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { createTypedTable } from 'vue-datatables-182'
import 'vue-datatables-182/dist/index.css'

type Invoice = {
  id: number
  name: string
  amountCents: number
}

const { DataTable, DataTableColumn } = createTypedTable<Invoice>()
const openedId = ref<number | null>(null)
const items: Invoice[] = [{ id: 1, name: 'Счёт за услуги', amountCents: 125000 }]
</script>

<template>
  <DataTable
    :items="items"
    row-key="id"
    scroll-x
    source="local"
  >
    <DataTableColumn
      field="name"
      sticky="left"
      title="Название"
      width="180px"
    />
    <DataTableColumn
      key="amount"
      sortable
      text-align="right"
      title="Сумма"
      :value="(item) => item.amountCents / 100"
    >
      <template #cell="{ item }">{{ (item.amountCents / 100).toFixed(2) }} ₽</template>
    </DataTableColumn>
    <DataTableColumn
      key="actions"
      sticky="right"
      title="Действия"
      width="140px"
    >
      <template #cell="{ item }">
        <button
          type="button"
          @click.stop="openedId = item.id"
        >
          Открыть
        </button>
      </template>
    </DataTableColumn>
  </DataTable>
  <output v-if="openedId !== null">Открыта запись № {{ openedId }}</output>
</template>
```

Для удалённой сортировки вычисляемой суммы добавляется
`sort-field="amount_cents"`. Сервер получает `amount_cents`, а `sort.by`
остаётся `amount`.

## Реактивное обновление

`v-for`, `v-if` и `Fragment` поддерживаются. При стабильном ключе изменение
`title`, `width`, `sticky`, `class`, `value`, настроек текста и слотов не
пересоздаёт таблицу. Изменение обработки значения обновляет локальные данные;
чисто визуальные изменения не запускают удалённый запрос.

Примеры находятся в группах «Интеграция» и «Прокрутка и закрепление»
в [Storybook](storybook.md). Правила темы описаны в [кастомизации](customization.md).
