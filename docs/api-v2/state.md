# Состояние таблицы

[Публичный контракт](../api-v2.md) · [Таблица](../data-table.md)

Таблица хранит поисковую строку, сортировку, номер и размер страницы,
а также выбранные ключи. Для каждого поля отдельно определяется, кто управляет
значением: сама таблица или родительский компонент.

## Автономный и управляемый режимы

| Поле            | Управляемый параметр | Начальное значение        |
| --------------- | -------------------- | ------------------------- |
| Страница        | `page`               | `defaultPage`             |
| Размер страницы | `rowsPerPageCount`   | `defaultRowsPerPageCount` |
| Поиск           | `searchQuery`        | `defaultSearchQuery`      |
| Сортировка      | `sort`               | `defaultSort`             |
| Выбор строк     | `selectedRowKeys`    | `defaultSelectedRowKeys`  |

Режим определяется при создании экземпляра. Значение управляемого параметра,
отличное от `undefined`, включает управление родителем. Для `sort` значение
`null` допустимо и означает управляемое состояние без сортировки.
Смена режима после создания не поддерживается; требуется новый экземпляр.

В автономном режиме начальный параметр читается один раз. Дальнейшие действия
изменяют внутреннее состояние. Изменение `defaultPage` уже созданной таблицы
не переводит её на другую страницу.

В управляемом режиме параметр родителя является источником значения.
Действие отправляет событие `update:…`, но новое значение применяется только
после обновления параметра родителем. Модели `v-model` связывают эти две операции.

### Пример перехода

При `page=2` нажатие на страницу `3` отправляет `update:page` со значением `3`.
Если родитель не обновил `page`, таблица остаётся на странице `2`.
В автономном режиме то же действие сразу меняет страницу.

События обновления доступны в обоих режимах и отправляются только при изменении
предлагаемого значения. Получение корректного значения от родителя не вызывает
ответного события. Массивы сравниваются по последовательности ключей,
сортировка — по `by` и `direction`, а не по ссылке на объект.

## Объединение изменений

Изменения одного цикла `Vue` объединяются. Сначала применяется исходное изменение,
затем рассчитываются зависимые ограничения страницы и выбора. Обработка данных
выполняется по конечному эффективному состоянию.

В управляемом режиме предложение нового значения само по себе не запускает
запрос: требуется подтверждение родителем. Обязательные ограничения зависимых
полей действуют сразу. Например, после подтверждённого нового поиска эффективная
страница становится `1`, даже если родитель ещё хранит прежний номер страницы.
Таблица отправляет предложение исправления.

Для полностью управляемого состояния родитель должен принимать также зависимые
события `update:page` и `update:selectedRowKeys`.

## Нормализация значений

Нормализация приводит входные значения к допустимому состоянию.

| Параметр             | Правило                                                                                            |
| -------------------- | -------------------------------------------------------------------------------------------------- |
| `page`               | Конечное положительное целое; дробная часть отбрасывается, неправильное значение заменяется на `1` |
| `rowsPerPageCount`   | Конечное положительное целое; неправильное значение заменяется на `25`                             |
| `rowsPerPageOptions` | Неправильные элементы и повторы удаляются; текущий размер добавляется в копию списка               |
| `searchQuery`        | Хранится без удаления пробелов; при обработке пробелы по краям удаляются                           |
| `sort`               | `{ by, direction }` либо `null`; неправильный ключ или направление очищают сортировку              |
| `selectionLimit`     | Неотрицательное целое или `null`; неправильное значение является ошибкой конфигурации              |
| `rowKey`             | Строка или конечное число; ключи должны быть уникальны                                             |

Верхняя граница `page` определяется количеством результатов `filtered`
и размером страницы. До первого удалённого ответа эта граница неизвестна;
номер не ограничивается исходным нулевым количеством записей.

Если список размеров пуст, отображается текущий размер. Входной массив
`rowsPerPageOptions` не изменяется. Отключение поиска очищает эффективную строку.

`sort.by` должен ссылаться на существующую колонку с `sortable=true`.
Направление — `asc` или `desc`. Удаление колонки очищает связанную сортировку.

Для `rowKey` пустая строка допустима, но `null`, `undefined`, `NaN` и бесконечность
запрещены. Число `1` и строка `'1'` — разные ключи. В локальном режиме проверяется
весь исходный набор; в удалённом — каждый ответ сервера.

Для неправильного управляемого значения предложение исправления отправляется
один раз на данный вход. Если родитель не принимает исправление, повторяющийся
цикл событий не создаётся. Ошибки статической конфигурации представлены `Error`;
ошибки удалённого ответа — состоянием ошибки и `requestError`.

## Переходы состояния

| Изменение                              | Последствия                                                                                       |
| -------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `page`                                 | Нормализация страницы и очистка выбора                                                            |
| `rowsPerPageCount`                     | Переход на страницу `1` и очистка выбора                                                          |
| `searchQuery`                          | Переход на страницу `1` и очистка выбора, включая режим без пагинации                             |
| `sort`                                 | Переход на страницу `1` и очистка выбора, включая режим без пагинации                             |
| `items` или новый удалённый ответ      | Обновление количества, ограничение страницы и согласование выбранных ключей                       |
| `filter`                               | В удалённом режиме — страница `1`, очистка выбора и новый запрос; в локальном режиме игнорируется |
| `source` или `url`                     | Отмена прежней работы, очистка данных, ошибки и выбора; страница `1`, новый источник              |
| `requestAdapter` или `responseAdapter` | В удалённом режиме — отмена прежней работы и обновление данных                                    |
| `rowKey`                               | Очистка выбора и повторная проверка ключей                                                        |
| `selection=false`                      | Очистка выбора                                                                                    |
| Уменьшение `selectionLimit`            | Сохранение первых допустимых ключей в порядке выбора                                              |
| `pagination=false`                     | Эффективная страница `1`, очистка выбора и обновление данных                                      |
| Состав или обработка колонок           | Обновление отображения, поиска и сортировки; удаление недопустимой сортировки                     |
| Оформление колонок или `density`       | Обновление интерфейса без нового удалённого запроса                                               |

Повторная установка эквивалентного значения ничего не сбрасывает.
Изменения `items` и `filter` учитываются глубоко; исходные массивы и объекты
не изменяются библиотекой.

Зависимости внутри `value` и `cell` учитываются при отрисовке `Vue`.
Если внешнее значение влияет на локальную обработку, но входные параметры
не менялись, для повторного расчёта предусмотрен `reload()`.

## Выбор строк

Выбор ограничен текущими видимыми записями. `selectionLimit=0` запрещает выбор,
`null` снимает ограничение, значение по умолчанию — `1000`.

Флажок заголовка выбирает первые строки в отображаемом порядке до лимита.
При полном выборе повторное нажатие снимает выбор. Если лимит меньше размера
страницы, флажок остаётся частично выбранным; повторное нажатие не изменяет
уже выбранный допустимый набор.

При отсутствии строк флажок заголовка не выбран и недоступен.
Во время загрузки, ошибки и при нулевом лимите элементы выбора недоступны.

Согласование ключей сохраняет порядок выбора, удаляет повторы и ключи,
которые больше не представлены видимыми строками. До первого удалённого
ответа начальные ключи ожидают проверки. После ответа отсутствующие ключи
удаляются. Передача ключей другой страницы приводит к нормализованному предложению.

## Порядок событий

Для одного действия события обновления следуют в порядке:

1. Исходное изменённое поле.
2. Зависимая страница.
3. Зависимый выбор строк.

Отправляются только события изменившихся значений. Повторное событие страницы
в пределах одного действия не создаётся.

`selectionChange` следует за фактическим изменением эффективных ключей.
В управляемом режиме это происходит после подтверждения родителем либо
нормализации обязательного ограничения. Поле `items` события содержит видимые
записи в порядке `keys`. Обновление содержимого записи с прежним ключом
само по себе не создаёт `selectionChange`.

## Типичные ситуации

| Ситуация                                          | Результат                                                                 |
| ------------------------------------------------- | ------------------------------------------------------------------------- |
| В автономном режиме размер изменён с `25` на `50` | Новый размер сохраняется при следующем обновлении                         |
| На странице `4` поиск оставил одну страницу       | Страница становится `1`, выбор очищается                                  |
| Выбранная запись удалена из `items`               | Её ключ исключается из выбора                                             |
| Внешнее управляемое значение не принято родителем | Отображается прежнее подтверждённое значение с обязательной нормализацией |
| Меняется только флажок выбора                     | Удалённый запрос не запускается                                           |
| При `pagination=false` меняется `page`            | Эффективная страница остаётся `1`                                         |

Пример использования моделей находится в [справочнике таблицы](../data-table.md).
