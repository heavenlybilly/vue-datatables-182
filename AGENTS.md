# Инструкции по работе с `vue-datatables-182`

Инструкции действуют для всего репозитория. Ручное редактирование выполняется
через `vim`. Изменения пользователя сохраняются. Необходимые зависимости
устанавливаются и обновляются в рамках задачи без отдельного согласования;
`package-lock.json` синхронизируется с `package.json`.

## Проект и контракт

Основа проекта — `Vue ^3.5.0`, `Composition API`, `TypeScript` и `CSS Grid`
с табличными ролями `ARIA`. Основной контракт описан в [API 2.0](docs/api-v2.md),
пользовательские справочники — [DataTable](docs/data-table.md) и
[DataTableColumn](docs/data-table-column.md). Переход с `1.x` описан в
[руководстве по миграции](docs/migration-guide.md), статус выпуска — в
[плане релиза](docs/major-release-plan.md).

Реализуется `API 2.0`, но в `package.json` пока указана версия `1.3.0-alpha.0`.
Изменение версии является отдельной задачей выпуска.

Поддерживаются локальные и удалённые данные, одна сортировка, поиск, пагинация,
выбор текущей страницы, слоты состояний, закрепление и локализация. Поддержка
`Vue 2`, виртуализация, несколько одновременных сортировок и перенос выбора
между страницами не входят в `2.0`.

## Команды

Окружение — `Node 24`. Установка зависимостей — `npm ci`.

| Команда                                       | Результат                                                                                                                        |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `npm run check:types`                         | Проверка типов через `vue-tsc` без создания файлов                                                                               |
| `npm test`                                    | Тесты `Vitest` и отчёт покрытия `V8`                                                                                             |
| `npm run test:watch`                          | Тесты в режиме наблюдения                                                                                                        |
| `npm run lint` / `npm run lint:fix`           | `ESLint` и `Prettier`, включая сценарии и проверочные приложения                                                                 |
| `npm run stylelint` / `npm run stylelint:fix` | Проверка `SCSS` и стилей компонентов `Vue`                                                                                       |
| `npm run check:code`                          | Типы, тесты и линтеры                                                                                                            |
| `npm run build`                               | Код через `Vite`, декларации через `vue-tsc`/`Rollup`, проверенные файлы в `dist`                                                |
| `npm pack`                                    | Сборка через `prepack` и создание архива                                                                                         |
| `npm run check:package`                       | Проверка установленного архива: примеры, `Vue`/`TypeScript`, `Vite`/`Webpack 5`, серверный рендеринг и восстановление на клиенте |
| `npm run storybook`                           | Каталог сценариев на `http://localhost:6006`                                                                                     |
| `npm run build:storybook`                     | Статический каталог в `storybook-static`                                                                                         |
| `npm run benchmark:local`                     | Измерения локальной обработки и монтирования в `jsdom`                                                                           |

Команда `check:package` устанавливает зависимости временного приложения
и не запускает сервер. Параметр `--keep` сохраняет приложение для диагностики:
`npm run check:package -- --keep`. Интерактивные сценарии находятся в `Storybook`.

## Архитектура

- `Core`: `useOwnedField`, `useQueryState`, `useSelectionState` и нормализация переходов.
- `DataProvider`: обработка локальных записей без мутаций, HTTP-адаптеры,
  отложенный запуск, отмена запросов и `reload`.
- `ColumnRegistry`/`ColumnObserver`: декларативные колонки, проверка конфигурации
  и реактивные метаданные.
- `Controller`: обработчики действий и вычисленные данные интерфейса.
- `Layout`: отображение, общие дорожки сетки, смещения закрепления, состояния
  и стандартные элементы управления.
- Плагин и локализация: `provide`/`inject` в пределах приложения,
  без изменяемой конфигурации на уровне модуля.

Реализация находится в
`src/components/{core,data,columns,controller,layout,plugin,localization}`.
Тесты — `tests/`, сценарии — `stories/`, настройки `Storybook` — `.storybook/`,
сборка — `config/`, проверочное приложение — `scripts/package-check/`.

Поток данных: параметры → `Core` → `DataProvider` → `Controller` → `Layout`.
Синхронизация объединяет изменения одного цикла обновления. Визуальные изменения
и выбор не запускают запрос. Серверный рендеринг локальной таблицы включает
колонки и строки; удалённый запрос начинается после монтирования.

## Оформление кода

Файлы имеют одну ответственность и небольшой размер. Лишние комментарии
и отладочный `console.log` исключаются. Имена функций композиции — `useName.ts`,
компонентов — `PascalCase.vue`, утилит — `kebab-case.ts`.

В `src` и `scripts` непустые объекты и объектные типы записываются на нескольких
строках. Условия `if`/`else` оформляются блоками с фигурными скобками.
Пустые строки отделяют смысловые группы; связанные последовательные вызовы
и присваивания располагаются вместе. Сжатие кода ради уменьшения числа строк
не допускается.

Применяются действующие правила `ESLint`, `Prettier` и `Stylelint` без отключения
ради отдельной правки. Отступ — два пробела, точки с запятой отсутствуют,
кавычки одинарные, завершающие запятые сохраняются. Атрибуты `Vue` располагаются
по алфавиту, по одному на строку; события в шаблонах записываются в `kebab-case`.
Порядок импортов определяется `.prettierrc.json`; для `src/` используется `@/`.

## Типы и поведение

Публичные типы находятся в `src/types/*.ts`, точка входа — `src/index.ts`.
Контракт слотов и экземпляров генерируется из однофайловых компонентов `Vue`.
Фабрика `createTypedTable<Item>()` специализирует исходные компоненты без
обёрток во время выполнения; обычные импорты сохраняют общий тип `RowItem`.
Строгая типизация проверяется в `scripts/package-check`, включая ожидаемые
ошибки в слотах шаблонов. Автоматический вывод типа записи из `items`
для слотов шаблона не обещается. Подсказки параметров, слотов, событий
и методов сохраняются; ручные заглушки не заменяют сгенерированные декларации.

Параметры компонентов, `items` и параметры `VNode` не мутируются.
Управляемый режим определяется при монтировании, начальные параметры читаются
один раз. Ключи колонок стабильны; обычные обновления не требуют повторного
монтирования. Ширина закреплённой колонки — положительная величина в `px`.
Слот `cell` меняет отображение; поиск и сортировка используют `value` или `field`.

Оформление задаётся публичными CSS-переменными с запасными значениями `var()`,
без перекрытия темы родителя. Контракт — [оформление](docs/customization.md).
Сортировку активирует только отдельная кнопка полной высоты. Слот `header`
меняет содержимое заголовка. Флажок сохраняет стандартный `input`.
Плотность, оформление и слоты не инициируют удалённый запрос.

Параметр `rowKey` обязателен: уникальная строка или конечное число. Выбор
ограничен текущей страницей и не инициирует запрос. Действия оформляются
обычной `DataTableColumn` со слотом `cell`; отдельного слота `actions` нет.
Интерактивные элементы внутри ячейки используют `@click.stop`, если нажатие
не должно выбирать строку. Кнопки и поля — стандартные HTML-элементы
с доступными именами и клавиатурным управлением.

Доступ к `window` и `document` учитывает серверный рендеринг.
Обработчики событий, таймеры и запросы освобождаются при завершении работы.

## Проверка изменений

- Изменения поведения сопровождаются проверкой регрессии в `tests/`.
  `Vitest` использует `jsdom`, явные импорты и восстановление подмен.
  Проверяется результат, а не внутренняя реализация.
- Изменения кода и API проверяются через `check:code`, стили — также через `stylelint`.
- Экспорты, декларации, сборка и примеры документации проверяются через
  `check:package`: архив, приложения `Vue`/`TypeScript`, сборщики, серверный
  рендеринг, восстановление на клиенте и сохранение CSS.
- Сценарии проверяются через `build:storybook` и соответствующие интерактивные
  проверки в браузере. Сборка каталога сама по себе не выполняет эти проверки.
- Для документации проверяются ссылки и форматирование; для `SVG` — XML
  и отображение. Полный набор проверок кода без причины не повторяется.
- Изменение публичного контракта отражается в справочниках, миграции,
  `CHANGELOG` и сценариях.

Ручные сценарии описаны в [руководстве Storybook](docs/storybook.md).

## Сборка и выпуск

Формат пакета — `ESM`, `CSS` и типы. Единственная внешняя зависимость — `Vue`.
Целевая настройка JavaScript и CSS — `firefox84`. API браузера и свойства CSS,
отсутствующие в `Firefox 84.0`, используются только с совместимым запасным
решением. Настройка сборки преобразует синтаксис, но не добавляет полифиллы API
среды выполнения.

Зависимости разработки `Vue` и `@vue/server-renderer` закреплены на `3.5.0`
для совместимых деклараций; диапазон зависимости потребителя — `^3.5.0`.
Архив ограничен тремя файлами `dist`, `readme.md`, `LICENSE` и `package.json`.
Экспортируются `dist/index.js`, `dist/index.d.ts` и отдельный `dist/index.css`.
CSS отмечен в `sideEffects`.

Сборка создаёт `build/package` и переносит файлы в `dist` после проверки.
Каталог `build/types` содержит промежуточные декларации; итоговый
`dist/index.d.ts` обязателен. Сгенерированные файлы не редактируются вручную.
При ошибке сборки `dist` удаляется. Команда `npm pack` запускает сборку через `prepack`.

В `CI` используется `Node 24`: типы, тесты, линтеры,
`test:release`, `check:package`, `build:storybook` и `test:storybook` в `Chromium`.
Браузерные проверки используют `config/storybook-tests.ts` и интеграцию
`Storybook` с `Vitest`. Плагины `Vue` берутся из `Storybook` и не добавляются
повторно в конфигурацию тестов.

Команда `check:package -- --output release` сохраняет только проверенный архив
и манифест `SHA-512`. Команда `check:release` проверяет точное соответствие
`v<version>`, поддерживает каналы `alpha`, `beta`, `rc` и `latest` для стабильной
версии; при передаче архива сверяет метаданные и контрольную сумму.
После успешного завершения проверок публикация получает артефакт `Node 24`
и запускает `npm publish` для архива с `--ignore-scripts`, без пересборки.
Авторизация публикации — `Trusted Publishing` через `OIDC`; право
`id-token: write` предоставлено только заданию публикации. Секрет `NPM_TOKEN`
не используется. Настройка аккаунтов описана в [публикации](docs/publishing.md).
Создание тегов выпуска и публикация требуют прямого запроса пользователя.

Ручные проверки `Firefox 84.0` и актуального `Firefox` являются обязательными
условиями выпуска. Они выполняются пользователем по [перечню проверок](docs/storybook.md).
Модульные тесты и сборка `Storybook` не подтверждают их прохождение.
